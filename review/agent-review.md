### [已修复 / 原 P2] 存档校验接受无法继续的阶段资源记录

位置：`src/state.js:10–18`；关联 `src/objectives.js:18,33–39`。

`validate` 独立检查 `counts` 和 `collected` 的类型，没有检查阶段资源 ID 范围及二者的一致性。复现：取 `fresh()`，保留全部计数为 0，设置 `collected = ['nutrient-0','nutrient-1','nutrient-2']`，经 JSON 存储再调用 `readSave`。该记录被接受且显示“继续上次的探索”；恢复后，所有三个营养点均隐藏，营养进度却是 0/3，既无法再收集也无法演化。应拒绝不一致数据或从当前阶段有效收集 ID 重建计数，向玩家提供已有的损坏存档提示。

同一校验入口还使用 `byId[raw.species]` 的真值判定 ID；`constructor` / `toString` 等继承属性不是合法生物但会通过此判定。`raw.unlocked` 有同样问题。建议使用 `Object.hasOwn(byId, id)`，并检查物种阶段、事件及分叉快照的基本一致性。

复查结果：当前 `validate` 已改为 `Object.hasOwn` 检查物种和图鉴 ID，按当前阶段需求限制资源 ID 范围，核对去重后的收集数与各资源计数一致。原始复现输入现在被拒绝。独立重新运行 `node --test scripts/state.test.mjs`：4 项测试全部通过，覆盖完整链路与三分支、资源记录损坏、继承属性/版本/位置/分叉记录、不可用存储及无效 JSON。

## 已运行的独立检查

- 未满足条件时无法演化，且不能越级选择非法目标。
- 单细胞收集 3 份营养后解锁鞭毛；鞭毛缺少同类聚集条件时不能演化。

- 三种终点均进入 ENDING；JSON 序列化、校验、分叉恢复后仍可选其余路线。
- 连续返回分叉并完成三条路线，图鉴累计保留全部 7 种生物。
- 对当前地形/碰撞约束做了网格抽样；发现个别资源点再约束时位置会变化，但抽查可由上方进入采集半径，因此不作为确定的不可达缺陷报告。
